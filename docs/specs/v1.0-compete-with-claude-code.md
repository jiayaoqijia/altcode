# v1.0 — Compete with Claude Code on Agent/Harness Management

## Competitive Position

**Altcode leads on:** CI auto-fix loop, review dispatch, lifecycle state machine, multi-agent workspace with git worktrees, GitHub API integration.

**Altcode trails on:** Process persistence (agents die on terminal close), session resume (doesn't re-attach), claude multi-turn (one-shot only).

## Top 3 Critical Gaps

### 1. Background Process Persistence (agents survive terminal close)

**Problem:** `processRuntime` ties agents to parent PID. Terminal close = all agents die.

**Fix:** Detach agent processes into their own process group. Write PIDs to disk. Re-attach on resume.

```go
cmd.SysProcAttr = &syscall.SysProcAttr{Setsid: true} // new process group
```

Store to `.altcode/workspace/{id}/pids.json`:
```json
{"architect": {"pid": 1234, "started_at": "..."}, ...}
```

### 2. True Session Resume (re-attach to live agents)

**Problem:** `workspace resume` sets status=working but doesn't re-spawn or re-attach.

**Fix:** On resume:
1. Read pids.json
2. Check each PID alive via Signal(0)  
3. Re-register OnOutput callbacks for live agents
4. Re-spawn dead agents with --resume {session_id}
5. Restart poll loop

### 3. Claude Backend Multi-Turn

**Problem:** Claude backend uses `claude --print` (one-shot). Can't iterate.

**Fix:** Use `claude --output-format stream-json --permission-mode bypassPermissions` without `--print`, keeping stdin open for follow-up turns. Parse stream-json for tool calls, thinking, results.
