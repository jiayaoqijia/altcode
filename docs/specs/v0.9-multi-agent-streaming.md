# v0.9 Multi-Agent Streaming & Multi-Turn — Design Spec

**Status:** Draft
**Date:** 2026-04-08
**Goal:** Make `altcode workspace` show live agent output in TUI panes and support multi-turn codex execution via JSON-RPC.

---

## Phase 1: Live Streaming to TUI Panes

### Problem
Agent stdout goes to terminal via `io.MultiWriter`. The TUI's `WorkspaceView` panes are empty during execution — users can't see what agents are doing.

### Solution
Replace `io.MultiWriter(os.Stdout, &buf)` with a pipe-based streaming system that feeds lines to `wsView.AppendAgentOutput(role, line)` in real-time.

### Design

**File: `cmd/altcode/workspace.go` — modify `processRuntime`**

```go
type processRuntime struct {
    mu        sync.Mutex
    procs     map[string]*os.Process
    outputs   map[string]*bytes.Buffer
    exits     map[string]int
    callbacks map[string]func(string) // handle ID → line callback
}

func (p *processRuntime) OnOutput(handleID string, cb func(line string)) {
    p.mu.Lock()
    defer p.mu.Unlock()
    if p.callbacks == nil {
        p.callbacks = make(map[string]func(string))
    }
    p.callbacks[handleID] = cb
}
```

In `Spawn`, replace `io.MultiWriter` with a pipe + scanner goroutine:

```go
pr, pw := io.Pipe()
cmd.Stdout = pw
cmd.Stderr = pw

go func() {
    scanner := bufio.NewScanner(pr)
    scanner.Buffer(make([]byte, 0, 64*1024), 1024*1024)
    for scanner.Scan() {
        line := scanner.Text()
        buf.WriteString(line + "\n")
        p.mu.Lock()
        cb := p.callbacks[h.ID]
        p.mu.Unlock()
        if cb != nil {
            cb(line)
        }
    }
}()
```

**File: `cmd/altcode/workspace.go` — modify `runWorkspaceStart`**

After spawning each agent, register a callback:

```go
rt.OnOutput(handle.ID, func(line string) {
    if wsView != nil {
        wsView.AppendAgentOutput(rec.Role, line)
    }
})
```

**File: `internal/tui/workspace_run.go` — modify `handleWorkspacePoll`**

The poll tick already calls `UpdateAgent` for metadata. With streaming callbacks, the pane's `Lines` buffer is populated in real-time. The poll tick just needs to trigger a re-render (which Bubbletea does automatically on any Msg).

## Phase 2: Multi-Turn Codex via JSON-RPC

### Problem
`codex exec` is one-shot: run task, exit. The agent can't iterate (read file → edit → test → fix). Multi-turn is essential for complex tasks.

### Solution
Use `codex app-server --listen stdio://` with JSON-RPC 2.0 protocol (same as multica). This keeps codex alive for multiple turns.

### Design

**File: `internal/workspace/backends/codex_rpc.go` (~200 lines)**

```go
type CodexRPCClient struct {
    cmd     *exec.Cmd
    stdin   io.WriteCloser
    stdout  io.ReadCloser
    scanner *bufio.Scanner
    mu      sync.Mutex
    nextID  int
    pending map[int]chan rpcResult
    threadID string
    onEvent func(CodexEvent)
}

type CodexEvent struct {
    Type    string // "text", "tool_start", "tool_done", "turn_done"
    Content string
    Tool    string
}

type rpcResult struct {
    Result json.RawMessage
    Err    error
}
```

**Lifecycle:**

```
1. Start: codex app-server --listen stdio://
2. Handshake: initialize({clientInfo, capabilities})
3. Create thread: thread/start({cwd, sandbox:"workspace-write"})
4. Send task: turn/start({threadId, input:[{type:"text", text:task}]})
5. Stream events: tool starts, outputs, turn completion
6. Auto-approve: respond to requestApproval with {decision:"accept"}
7. On turn complete: check results, optionally send follow-up turn
8. Cleanup: close stdin → codex exits
```

**Methods:**

```go
func NewCodexRPCClient(ctx context.Context, workdir string, env []string) (*CodexRPCClient, error)
func (c *CodexRPCClient) SendTurn(ctx context.Context, prompt string) error
func (c *CodexRPCClient) Wait(ctx context.Context) (*TurnResult, error)
func (c *CodexRPCClient) Close() error
```

**Integration with workspace:**

```go
// In workspace spawn path, use RPC client instead of exec:
if backend == "codex" && useRPC {
    client, err := NewCodexRPCClient(ctx, worktreePath, env)
    // Register event callback for TUI streaming
    client.onEvent = func(ev CodexEvent) {
        wsView.AppendAgentOutput(role, formatEvent(ev))
    }
    // Send the task
    client.SendTurn(ctx, task)
    // Wait for completion
    result, err := client.Wait(ctx)
}
```

## Phase 3: Manager Agent + Result Synthesis

### Problem
3 agents work independently. Nobody merges their outputs or resolves conflicts.

### Solution
After all workers complete, run a manager agent that reads all outputs and creates a unified result.

**File: `internal/workspace/manager.go` (~80 lines)**

```go
func RunManager(ctx context.Context, cfg ManagerConfig) (*ManagerResult, error) {
    // Build prompt with all worker outputs
    prompt := buildManagerPrompt(cfg.Task, cfg.WorkerOutputs)
    // Run via codex or claude
    stream := agent.SpawnExternal(ctx, agent.ExternalAgentConfig{
        Backend: agent.BackendCodex,
        Role:    "manager",
        WorkDir: cfg.WorkDir,
        Task:    prompt,
    })
    // Collect result
    // ...
}
```

**Manager prompt:**
```
You are the manager agent. Your workers completed these tasks:

=== architect ===
[architect's output]

=== implementer ===
[implementer's output]

=== reviewer ===
[reviewer's output]

Merge all changes into a coherent result. Resolve any conflicts.
Create a single commit with all changes.
```

## Phase 4: Branch Merging + PR Creation

After the manager synthesizes, merge all agent branches:

```go
func MergeAgentBranches(ctx context.Context, gitRoot, baseBranch string,
    agents map[string]*workspace.AgentRecord) (string, error) {
    
    mergeBranch := fmt.Sprintf("altcode/merge/%s", sess.ID[:8])
    runGit(ctx, gitRoot, "checkout", "-b", mergeBranch, baseBranch)
    
    for _, rec := range agents {
        // Cherry-pick each agent's commits
        commits := getNewCommits(ctx, rec.WorktreePath, baseBranch)
        for _, sha := range commits {
            runGit(ctx, gitRoot, "cherry-pick", sha)
        }
    }
    return mergeBranch, nil
}
```
