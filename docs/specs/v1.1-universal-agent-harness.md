# v1.1 Universal Agent Harness — Orchestrate Any CLI Agent

## Vision

altcode becomes a **universal agent harness** — like Linear for coding agents.
It doesn't care what the agent IS, only that it can be launched as a CLI process.
Any agent that accepts a task via argv and produces output on stdout is a first-class citizen.

```
altcode workspace "build auth system"
  ├── claude-code (architect)   ← full Claude Code with worktree + hooks
  ├── codex-rpc (implementer)   ← Codex via JSON-RPC multi-turn
  ├── altcode (tester)          ← altcode itself, recursively
  ├── openclaw (security)       ← OpenClaw agent
  └── custom-agent (reviewer)   ← any CLI: hermes, devin-cli, etc.
```

## Architecture: Agent Registry

Instead of hardcoded backends, use a **plugin registry** where any CLI agent
can be registered with its launch configuration.

### Agent Definition Format

`.altcode/agents/{name}.yaml`:

```yaml
name: claude-code
binary: claude
args:
  - "--output-format"
  - "stream-json"
  - "--permission-mode"
  - "bypassPermissions"
  - "--max-turns"
  - "50"
task_flag: "-p"           # how to pass the task (append to args)
worktree: true            # launch in its own git worktree
resume_flag: "--resume"   # flag for session resume (optional)
session_id_env: ""        # env var that receives session ID
detect: "claude --version"  # how to check if installed
```

```yaml
name: codex-rpc
binary: codex
mode: json-rpc            # "exec" (one-shot) or "json-rpc" (multi-turn)
args:
  - "app-server"
  - "--listen"
  - "stdio://"
worktree: true
detect: "codex --version"
```

```yaml
name: altcode
binary: altcode
args: ["--json"]
task_flag: ""             # task is the first positional arg
worktree: true
detect: "altcode --help"
```

```yaml
name: openclaw
binary: openclaw
args:
  - "agent"
  - "--output-format"
  - "stream-json"
  - "--yes"
task_flag: "-p"
worktree: true
detect: "openclaw --version"
```

```yaml
name: custom
binary: "/path/to/my-agent"
args: ["--headless"]
task_flag: "--task"
worktree: false
detect: ""
```

### Universal Backend Interface

```go
// internal/workspace/backends/universal.go

type UniversalBackend struct {
    Name      string
    Binary    string
    Args      []string
    TaskFlag  string   // "-p", "--task", or "" (positional)
    Mode      string   // "exec" or "json-rpc"
    Worktree  bool
    ResumeFlag string
    DetectCmd  string
}

func (b *UniversalBackend) LaunchCommand(sess *AgentSession) ([]string, error) {
    argv := []string{b.Binary}
    argv = append(argv, b.Args...)
    if b.TaskFlag != "" {
        argv = append(argv, b.TaskFlag, sess.Task)
    } else {
        argv = append(argv, sess.Task)
    }
    return argv, nil
}
```

### Agent Discovery

1. Scan `.altcode/agents/*.yaml` in project
2. Scan `~/.config/altcode/agents/*.yaml` for user-global
3. Auto-detect installed binaries via `detect` command
4. Merge: project agents override global, detected agents are fallback

### TUI Integration

The workspace command accepts any registered agent:

```bash
# Use specific agents by name
altcode workspace "build auth" --agents claude-code,codex-rpc,altcode

# Use a custom agent
altcode workspace "security audit" --agents openclaw,custom

# Mix any agents
altcode workspace "full stack feature" \
  --agents claude-code:architect,codex-rpc:implementer,openclaw:reviewer
```

The TUI shows each agent in its own pane regardless of what it is.
