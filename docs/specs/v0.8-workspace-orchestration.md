## 1. Vision and Problem Statement

### 1.1 The Strategic Pivot

v0.7.0 shipped a phase-gated workflow engine (`internal/orchestra/`) that is genuinely useful but architecturally incomplete for the product direction described in `docs/business/pricing-and-direction.md`. The pivot from "workflow-driven" to "workspace-driven" orchestration is a deliberate strategic choice, not a refactor.

The difference matters:

**Workflow-driven (v0.7):** The workflow definition is the primary abstraction. Agents are servants of phases. Phases gate each other. The TUI shows phase progress. When the workflow ends, everything disappears.

**Workspace-driven (v0.8):** The git repository is the primary abstraction. The workspace is persistent state. Agents are tenants in the workspace. GitHub native artifacts (branches, PRs, CI runs, review comments) are first-class objects. The workspace persists across terminal sessions, machine restarts, and operator absence.

This mirrors how real engineering teams work: branches accumulate, PRs get reviewed asynchronously, CI re-runs, review comments trigger follow-ups. The workspace model makes altcode a native participant in this flow, not an external automation tool.

### 1.2 What Failed in v0.7.0

The v0.7.0 approach has several architectural gaps that surface immediately in real use:

**Gap 1: No persistent session identity.** When the terminal closes during a `ship-feature` workflow, all state is gone. The user cannot resume from where the agent stopped. The `ExternalAgentResult.SessionID` field was added but never plumbed into a resume path.

**Gap 2: No GitHub awareness.** The orchestra knows nothing about PRs, CI runs, or review comments. An agent can create a PR as a side effect, but the orchestrator has no way to detect this, poll its CI status, route review comments back to the agent, or merge it when approved.

**Gap 3: No worktree isolation per-agent.** All agents in a phase share the same `WorkDir`. This causes file conflicts during parallel phases. The `runPhaseParallel` function in `internal/orchestra/orchestra.go` injects context sequentially to avoid races, but the agents themselves still stomp on each other's file edits.

**Gap 4: No stuck detection.** If an agent hangs waiting for a permission prompt (which `handleClaudeControlRequest` should prevent but sometimes misses due to protocol changes), the workflow hangs forever. There is no watchdog.

**Gap 5: No attention triage.** The split-pane TUI shows all agents equally. Operators cannot tell at a glance which agent needs human intervention versus which is happily making progress.

**Gap 6: No CI auto-fix loop.** A PR created by an agent that fails CI is a dead-end. There is no mechanism to route the CI failure back to the agent, have it fix the issue, force-push, and re-check.

**Gap 7: Turn checkpoints are absent.** There is no per-turn snapshot mechanism. Rollback is impossible.

### 1.3 Why Workspace-Driven

The workspace model solves all seven gaps:

1. Persistent workspace directory (`.altcode/workspace/{id}/`) survives terminal close.
2. SCM plugin interface monitors PRs, CI, and review comments on a polling loop.
3. Per-agent git worktrees (`git worktree add`) give each agent a fully isolated working directory sharing the same `.git` object store.
4. Activity detection cascade (6 states) with process liveness check provides stuck detection.
5. Attention priority zones (red/orange/yellow/green) reduce operator cognitive load.
6. CI auto-fix loop with retry limit and escalation path.
7. Turn checkpoint: `git commit` after every agent turn creates a natural rollback point.

The workspace model also aligns with the business strategy: workspace persistence is the Cloud tier's killer feature. "Undo any agent action" (rollback to turn checkpoint) is worth $19/mo to a developer who has had an agent trash a file.

## 2. Architecture

### 2.1 Overview

v0.8 introduces six new packages and modifies four existing ones:

```
New packages:
  internal/workspace/      — WorkspaceSession, AgentRecord, flat-file persistence
  internal/lifecycle/      — State machine, polling loop, reactions
  internal/scm/            — SCM plugin interface + GitHub implementation
  internal/activity/       — Activity detection cascade (6 states)
  internal/checkpoint/     — Turn checkpoint: git commit + metadata append
  internal/wsctl/          — Workspace-level system prompt assembly

Modified packages:
  internal/agent/external.go   — Add MaxTurns, AppendSystemPrompt, Resume, SessionID output
  internal/orchestra/          — Add worktree setup, checkpoint hook, workspace-aware context
  internal/tui/               — Add WorkspaceView, attention zones, workspace header
  cmd/altcode/                 — Add workspace/spawn/status/send/review-check subcommands
```

The 8 plugin slots from `vendor/agent-orchestrator/CLAUDE.md` are adapted to Go interfaces. These interfaces live in `internal/workspace/plugin.go` and are the seams where v0.8 is extensible:

```go
package workspace

import (
    "context"
    "time"
)

// Runtime is where agents execute. Default: process (fork/exec).
// Alternative: tmux pane (for human observation), container.
type Runtime interface {
    // Spawn starts a command in the runtime, returning a handle.
    Spawn(ctx context.Context, cmd []string, env []string, workdir string) (RuntimeHandle, error)
    // Attach returns a reader that streams terminal output from an existing handle.
    Attach(ctx context.Context, handle RuntimeHandle) (<-chan string, error)
    // Kill terminates an active handle. Best-effort; may already be dead.
    Kill(handle RuntimeHandle) error
    // IsRunning checks whether the process is still alive.
    IsRunning(handle RuntimeHandle) (bool, error)
    // Name returns the runtime's identifier string, e.g. "process", "tmux".
    Name() string
}

// RuntimeHandle is an opaque reference to a running process.
// Implementations store whatever is needed (PID, tmux pane ID, container ID).
type RuntimeHandle struct {
    // ID is a stable, serializable identifier. Format is runtime-specific.
    // process runtime: "pid:1234"
    // tmux runtime:    "tmux:altcode-abc123:0"
    ID string
    // StartedAt is when the process was spawned.
    StartedAt time.Time
}

// Agent is a pluggable AI coding tool backend.
// Implementations: claude, codex, opencode, aider.
type Agent interface {
    // LaunchCommand returns the argv to start this agent for the given session.
    // The session carries workdir, branch, task prompt, and resume info.
    LaunchCommand(session *AgentSession) ([]string, error)
    // Environment returns additional env vars required by the agent.
    // Must not include API keys — those come from the process environment.
    Environment(session *AgentSession) (map[string]string, error)
    // ActivityState returns the agent's current activity, consulting JSONL
    // and/or the native API. Returns nil if no data is available yet.
    ActivityState(ctx context.Context, session *AgentSession) (*ActivityDetection, error)
    // IsProcessRunning checks whether the agent process is still alive.
    IsProcessRunning(session *AgentSession) (bool, error)
    // SessionInfo extracts summary, cost, and session ID from the agent's
    // native data structures. Returns nil if the agent has no introspection.
    SessionInfo(ctx context.Context, session *AgentSession) (*AgentSessionInfo, error)
    // SetupWorkspaceHooks installs hooks that allow the workspace to track
    // metadata (PR numbers, commit hashes) without parsing agent output.
    // For claude: PostToolUse hooks in .claude/settings.json.
    // For codex/opencode/aider: PATH wrapper binaries in ~/.altcode/bin/.
    SetupWorkspaceHooks(session *AgentSession) error
    // RestoreCommand returns the argv to resume a prior session, or nil if
    // the backend has no session resume capability.
    RestoreCommand(session *AgentSession) ([]string, error)
    // Name returns the backend identifier, e.g. "claude", "codex".
    Name() string
}

// AgentSession carries all context needed to launch or restore an agent.
type AgentSession struct {
    // WorkspacePath is the root of the .altcode/workspace/{id} directory.
    WorkspacePath string
    // WorktreePath is the isolated git worktree root for this agent.
    WorktreePath string
    // Branch is the agent's git branch (e.g. "altcode/architect/auth-design").
    Branch string
    // Task is the high-level task description.
    Task string
    // Role is this agent's role (e.g. "architect", "implementer").
    Role string
    // Model is the AI model to use, e.g. "anthropic/claude-sonnet-4-20250514".
    // Empty means use the default for the backend.
    Model string
    // MaxTurns limits the agent's turn count. 0 means no limit.
    MaxTurns int
    // SystemPromptAppend is appended to the agent's system prompt, injecting
    // role-specific instructions without replacing the base system prompt.
    SystemPromptAppend string
    // PriorSessionID is the session ID from a previous run, for --resume.
    PriorSessionID string
    // Env contains the process environment (API keys, PATH, etc.).
    // The Agent.Environment() additions are merged on top of this.
    Env []string
    // AOSESSIONID is the workspace session ID, injected as env var.
    AOSessionID string
}

// AgentSessionInfo holds extracted metadata from an agent's native data.
type AgentSessionInfo struct {
    Summary   string
    Cost      float64 // USD
    SessionID string  // for --resume on next invocation
    Tokens    int
}

// Workspace manages code isolation per agent.
// Default: git worktree. Alternative: full clone.
type Workspace interface {
    // Setup creates an isolated workspace for an agent.
    // For worktree: git worktree add <path> -b <branch> <base>
    // For clone: git clone <url> <path> && git checkout -b <branch>
    Setup(ctx context.Context, req WorkspaceSetupRequest) (*WorkspaceSetupResult, error)
    // Teardown removes the isolated workspace when done.
    // For worktree: git worktree remove --force
    // For clone: rm -rf
    Teardown(ctx context.Context, path string) error
    // Checkpoint creates a git commit capturing the current workspace state.
    // Used for turn checkpoints and rollback.
    Checkpoint(ctx context.Context, path string, msg string) (string, error) // returns commit hash
    // Name returns the workspace type, e.g. "worktree", "clone".
    Name() string
}

// WorkspaceSetupRequest specifies what to create.
type WorkspaceSetupRequest struct {
    // GitRoot is the path to the bare .git or the main checkout root.
    GitRoot string
    // WorktreePath is where to create the worktree/clone.
    WorktreePath string
    // Branch is the new branch name to create.
    Branch string
    // BaseRef is the git ref to branch from (e.g. "main", "origin/main").
    BaseRef string
    // SymlinkDeps is a list of directories to symlink rather than copy.
    // Used for node_modules, .venv, vendor (Go modules use shared cache).
    SymlinkDeps []string
}

// WorkspaceSetupResult holds the outcome of a workspace setup.
type WorkspaceSetupResult struct {
    // Path is the absolute path to the workspace root.
    Path string
    // Branch is the actual branch name created (may have timestamp suffix
    // if the requested branch already existed).
    Branch string
    // BaseCommit is the git hash at branch creation time.
    BaseCommit string
}

// Tracker is an issue tracker integration. Default: github issues.
// Alternative: linear, gitlab, none.
type Tracker interface {
    // GetIssue fetches issue details by ID.
    GetIssue(ctx context.Context, id string) (*Issue, error)
    // UpdateIssue sets a label or comment on an issue.
    UpdateIssue(ctx context.Context, id string, update IssueUpdate) error
    // Name returns the tracker identifier, e.g. "github", "linear", "none".
    Name() string
}

// Issue holds issue metadata from the tracker.
type Issue struct {
    ID          string
    Title       string
    Description string
    Labels      []string
    URL         string
}

// IssueUpdate describes a modification to an issue.
type IssueUpdate struct {
    AddLabel    string
    RemoveLabel string
    Comment     string
}

// SCM is a source control management integration.
// It handles PR creation, CI status polling, and review comment routing.
// Default: github. Alternative: gitlab, none.
type SCM interface {
    // CreatePR creates a pull request from the agent's branch to the base.
    CreatePR(ctx context.Context, req CreatePRRequest) (*PR, error)
    // GetPR fetches current PR state including CI and review status.
    GetPR(ctx context.Context, id int) (*PR, error)
    // ListPRs returns open PRs whose heads start with the given prefix.
    ListPRs(ctx context.Context, headPrefix string) ([]*PR, error)
    // GetPRReviews returns review comments on a PR.
    GetPRReviews(ctx context.Context, prID int) ([]*Review, error)
    // RequestReview requests a review from specific reviewers.
    RequestReview(ctx context.Context, prID int, reviewers []string) error
    // MergePR merges the PR using the given method.
    MergePR(ctx context.Context, prID int, method MergeMethod) error
    // CIStatus polls the combined CI status for a commit.
    CIStatus(ctx context.Context, sha string) (CICheckStatus, error)
    // Name returns "github", "gitlab", etc.
    Name() string
}

// CreatePRRequest specifies what PR to create.
type CreatePRRequest struct {
    Title  string
    Body   string
    Head   string // branch name
    Base   string // target branch (e.g. "main")
    Draft  bool
    Labels []string
}

// PR holds pull request metadata.
type PR struct {
    ID           int
    Number       int
    Title        string
    URL          string
    HeadSHA      string
    HeadBranch   string
    BaseBranch   string
    State        string // "open", "closed", "merged"
    Draft        bool
    CIStatus     CICheckStatus
    ReviewStatus ReviewStatus
    MergeableState string // "mergeable", "conflicting", "unknown", "blocked"
    CreatedAt    time.Time
    UpdatedAt    time.Time
}

// Review holds a PR review.
type Review struct {
    ID        int
    Author    string
    State     string // "APPROVED", "CHANGES_REQUESTED", "COMMENTED"
    Body      string
    Comments  []ReviewComment
    SubmittedAt time.Time
}

// ReviewComment is a single inline comment on a PR diff.
type ReviewComment struct {
    Path     string
    Line     int
    Body     string
    Author   string
}

// CICheckStatus is the combined status of all CI checks.
type CICheckStatus string

const (
    CIUnknown  CICheckStatus = "unknown"
    CIPending  CICheckStatus = "pending"
    CIRunning  CICheckStatus = "running"
    CIPass     CICheckStatus = "pass"
    CIFail     CICheckStatus = "fail"
    CISkipped  CICheckStatus = "skipped"
)

// ReviewStatus is the aggregated review state of a PR.
type ReviewStatus string

const (
    ReviewNone              ReviewStatus = "none"
    ReviewApproved          ReviewStatus = "approved"
    ReviewChangesRequested  ReviewStatus = "changes_requested"
    ReviewCommented         ReviewStatus = "commented"
)

// MergeMethod controls how a PR is merged.
type MergeMethod string

const (
    MergeMerge  MergeMethod = "merge"
    MergeSquash MergeMethod = "squash"
    MergeRebase MergeMethod = "rebase"
)

// Notifier delivers notifications to operators.
// Default: none. Alternatives: desktop, slack, webhook.
type Notifier interface {
    // Notify sends a notification for the given workspace event.
    Notify(ctx context.Context, event NotifyEvent) error
    // Name returns "desktop", "slack", "webhook", "none".
    Name() string
}

// NotifyEvent carries the payload for a notification.
type NotifyEvent struct {
    // WorkspaceID is the short ID of the workspace.
    WorkspaceID string
    // Role is the agent role that triggered the event, or "" for workspace-level.
    Role string
    // Kind is the event type (see NotifyKind constants).
    Kind NotifyKind
    // Summary is a one-line human-readable description.
    Summary string
    // URL is an optional link (e.g. the PR URL).
    URL string
}

// NotifyKind identifies what happened.
type NotifyKind string

const (
    NotifyNeedsAttention NotifyKind = "needs_attention"  // stuck, waiting_input
    NotifyPROpen         NotifyKind = "pr_open"          // agent created a PR
    NotifyCIFailed       NotifyKind = "ci_failed"        // CI failed after retries
    NotifyApproved       NotifyKind = "approved"         // PR approved by reviewer
    NotifyMerged         NotifyKind = "merged"           // PR merged
    NotifyError          NotifyKind = "error"            // unrecoverable error
)

// Terminal is the human-attachment mechanism.
// Default: none (TUI handles everything). Alternative: iterm2-tab.
type Terminal interface {
    // Open opens a terminal window/pane showing the agent's runtime.
    Open(ctx context.Context, handle RuntimeHandle, title string) error
    // Name returns "iterm2", "tmux", "none".
    Name() string
}

    Runtime   Runtime

    Tracker   Tracker

    Notifier  Notifier
    Terminal  Terminal
```

```go
package workspace

import (
    "sync"
    "time"
)

// WorkspaceStatus is the coarse-grained lifecycle state of the whole workspace.
// Per-agent states are tracked in AgentRecord.ActivityState.
type WorkspaceStatus string

const (
    WSSSpawning          WorkspaceStatus = "spawning"
    WSSWorking           WorkspaceStatus = "working"
    WSSPROpen            WorkspaceStatus = "pr_open"
    WSSCIChecking        WorkspaceStatus = "ci_checking"
    WSSCIFailed          WorkspaceStatus = "ci_failed"
    WSSChangesRequested  WorkspaceStatus = "changes_requested"
    WSSApproved          WorkspaceStatus = "approved"
    WSSMergeable         WorkspaceStatus = "mergeable"
    WSSMerged            WorkspaceStatus = "merged"
    WSSCleanup           WorkspaceStatus = "cleanup"
    WSSDone              WorkspaceStatus = "done"
    WSSFailed            WorkspaceStatus = "failed"    // unrecoverable error
    WSSPaused            WorkspaceStatus = "paused"    // operator requested pause
)

// ActivityState is the fine-grained activity of a single agent process.
type ActivityState string

const (
    ActivitySpawning     ActivityState = "spawning"      // not yet launched
    ActivityActive       ActivityState = "active"        // working, output < 30s ago
    ActivityReady        ActivityState = "ready"         // idle 30s–5min
    ActivityIdle         ActivityState = "idle"          // idle > 5min
    ActivityWaitInput    ActivityState = "waiting_input" // blocked on permission prompt
    ActivityBlocked      ActivityState = "blocked"       // stuck on error
    ActivityExited       ActivityState = "exited"        // process dead
)

// WorkspaceSession is the central record for one workspace run.
// It is persisted to .altcode/workspace/{id}/session.json.
type WorkspaceSession struct {
    // ID is a ULID-format unique identifier.
    ID          string          `json:"id"`
    // Task is the human-readable task description.
    Task        string          `json:"task"`
    // Status is the current lifecycle state.
    Status      WorkspaceStatus `json:"status"`
    // GitRoot is the absolute path to the git repository root.
    GitRoot     string          `json:"git_root"`
    // BaseBranch is the branch agents branched from (e.g. "main").
    BaseBranch  string          `json:"base_branch"`
    // WorkflowName is the workflow that created this workspace, or "".
    WorkflowName string         `json:"workflow_name,omitempty"`
    // Agents holds per-agent records.
    Agents      map[string]*AgentRecord `json:"agents"`
    // CIRetries is the global CI auto-fix attempt counter.
    CIRetries   int             `json:"ci_retries"`
    // MaxCIRetries is the maximum auto-fix attempts (default 3).
    MaxCIRetries int            `json:"max_ci_retries"`
    // CreatedAt is when the workspace was created.
    CreatedAt   time.Time       `json:"created_at"`
    // UpdatedAt is the last time session.json was written.
    UpdatedAt   time.Time       `json:"updated_at"`
    // CompletedAt is set when status transitions to merged or done.
    CompletedAt *time.Time      `json:"completed_at,omitempty"`
    // Error holds the last unrecoverable error message.
    Error       string          `json:"error,omitempty"`

    mu sync.Mutex `json:"-"` // guards in-memory mutations
}

// AgentRecord tracks one agent within a workspace.
type AgentRecord struct {
    // Role is the human-readable role name, e.g. "architect".
    Role          string        `json:"role"`
    // Backend is the CLI tool name, e.g. "claude", "codex".
    Backend       string        `json:"backend"`
    // Model is the AI model in use.
    Model         string        `json:"model"`
    // Branch is the full git branch name.
    Branch        string        `json:"branch"`
    // WorktreePath is the absolute path to the agent's git worktree.
    WorktreePath  string        `json:"worktree_path"`
    // RuntimeHandleID is the opaque handle for the running process.
    RuntimeHandleID string      `json:"runtime_handle_id"`
    // SessionID is the agent's own session ID (for --resume).
    SessionID     string        `json:"session_id,omitempty"`
    // PRID is the GitHub PR number, 0 if no PR created yet.
    PRID          int           `json:"pr_id,omitempty"`
    // PRURL is the GitHub PR URL.
    PRURL         string        `json:"pr_url,omitempty"`
    // HeadSHA is the current HEAD commit hash.
    HeadSHA       string        `json:"head_sha,omitempty"`
    // ActivityState is the current fine-grained activity.
    ActivityState ActivityState `json:"activity_state"`
    // ActivityUpdatedAt is when ActivityState was last observed.
    ActivityUpdatedAt time.Time `json:"activity_updated_at"`
    // CIStatus is the last-known CI status for this agent's PR.
    CIStatus      CICheckStatus `json:"ci_status"`
    // ReviewStatus is the last-known review state.
    ReviewStatus  ReviewStatus  `json:"review_status"`
    // SpawnedAt is when the agent process was launched.
    SpawnedAt     time.Time     `json:"spawned_at"`
    // ExitedAt is when the process exited, if it has.
    ExitedAt      *time.Time    `json:"exited_at,omitempty"`
    // ExitCode is the process exit code (-1 if still running).
    ExitCode      int           `json:"exit_code"`
    // TurnCount is the number of completed agent turns.
    TurnCount     int           `json:"turn_count"`
    // CostUSD is the accumulated cost in USD.
    CostUSD       float64       `json:"cost_usd"`
}

// AttentionPriority classifies how urgently an agent needs operator attention.
type AttentionPriority int

const (
    AttentionGreen  AttentionPriority = 0 // working normally
    AttentionYellow AttentionPriority = 1 // auto-fix failed, monitoring
    AttentionOrange AttentionPriority = 2 // PR ready, review needed
    AttentionRed    AttentionPriority = 3 // stuck, needs immediate intervention
)

// Priority computes the operator attention priority for an agent.
// This is the core logic that drives the TUI color coding.
func (a *AgentRecord) Priority() AttentionPriority {
    switch a.ActivityState {
    case ActivityWaitInput, ActivityBlocked:
        return AttentionRed
    case ActivityExited:
        if a.ExitCode != 0 {
            return AttentionRed
        }
        if a.PRID > 0 && a.ReviewStatus == ReviewChangesRequested {
            return AttentionOrange
        }
        return AttentionGreen
    }
    // CI failed after exhausting retries
    if a.CIStatus == CIFail {
        return AttentionYellow
    }
    // PR open and waiting for review approval
    if a.PRID > 0 && a.ReviewStatus == ReviewNone {
        return AttentionOrange
    }
    return AttentionGreen
}
```

## 3. Session Lifecycle State Machine

### 3.1 State Diagram

```
                        ┌─────────────────────────────────────────────────────┐
                        │                    WORKSPACE LIFECYCLE               │
                        └─────────────────────────────────────────────────────┘

  altcode workspace <task>
          │
          ▼
    ┌──────────┐
    │ SPAWNING │  — workdir created, agents launching
    └──────────┘
          │ all agents have living processes
          ▼
    ┌─────────┐
    │ WORKING │  — agents are active/ready/idle; writing code
    └─────────┘
          │ any agent creates a PR (detected via hook/metadata)
          ▼
    ┌─────────┐
    │ PR_OPEN │  — at least one PR exists; waiting for CI
    └─────────┘
          │ CI jobs start running on the PR head commit
          ▼
    ┌─────────────┐
    │ CI_CHECKING │  — CI runs in progress; polling every 10s
    └─────────────┘
          │ CI passes                         │ CI fails
          ▼                                   ▼
    ┌──────────────────────────┐       ┌────────────────────────┐
    │ working (review pending) │       │ CI_FAILED              │
    └──────────────────────────┘       └────────────────────────┘
          │                                   │ retries < MaxCIRetries
          │                                   ▼
          │                            ┌─────────────────────────┐
          │                            │ WORKING (ci-fix branch) │
          │                            └─────────────────────────┘
          │                                   │ agent pushes fix, CI re-runs
          │                                   └──────► CI_CHECKING
          │
          │ reviewer submits CHANGES_REQUESTED
          ▼
    ┌────────────────────┐
    │ CHANGES_REQUESTED  │  — agent resumes in worktree, addresses comments
    └────────────────────┘
          │ agent pushes updated commits, re-requests review
          ▼
    ┌─────────────────────────┐
    │ CI_CHECKING (re-review) │
    └─────────────────────────┘
          │ CI passes AND review approved
          ▼
    ┌──────────┐
    │ APPROVED │  — all checks pass; waiting for merge gate
    └──────────┘
          │ mergeable_state == "mergeable" (no conflicts)
          ▼
    ┌───────────┐
    │ MERGEABLE │  — auto-merge triggered (if configured) or operator merges
    └───────────┘
          │ PR merged
          ▼
    ┌────────┐
    │ MERGED │  — PR is in the base branch
    └────────┘
          │ always
          ▼
    ┌─────────┐
    │ CLEANUP │  — remove worktrees, archive session files
    └─────────┘
          │ cleanup complete
          ▼
    ┌──────┐
    │ DONE │
    └──────┘

    At any state, operator can inject: PAUSED ──► WORKING (resume)
    At any state, CI retries exhausted: ──────► FAILED (terminal)
    At any state, agent process crash + no recover: FAILED
```

### 3.2 Transition Rules

Every state transition in `internal/lifecycle/lifecycle.go` follows this contract:

| From | To | Trigger | Guard | Action |
|------|----|---------|-------|--------|
| `spawning` | `working` | All agent processes alive (isProcessRunning == true for all) | At least one agent is active or ready | Emit `NotifyKind: working`; write session.json |
| `spawning` | `failed` | Any agent fails to start within 30s | — | Set session.Error; emit `NotifyError`; write session.json |
| `working` | `pr_open` | Any AgentRecord.PRID becomes nonzero (hook fires or poll detects) | PRID > 0 | Fetch PR details; populate AgentRecord.PRURL; write session.json |
| `pr_open` | `ci_checking` | PR.CIStatus transitions from `unknown`/`pending` to `running` | — | Record poll tick; write session.json |
| `ci_checking` | `working` | PR.CIStatus == `pass` AND PR.ReviewStatus == `none` | — | Emit `NotifyKind: pr_open` to request review; write session.json |
| `ci_checking` | `approved` | PR.CIStatus == `pass` AND PR.ReviewStatus == `approved` | — | Write session.json; attempt auto-merge if configured |
| `ci_checking` | `ci_failed` | PR.CIStatus == `fail` | — | Write session.json; start CI auto-fix loop |
| `ci_failed` | `working` | CI auto-fix dispatched to agent | session.CIRetries < MaxCIRetries | Increment CIRetries; inject CI failure into agent context; write session.json |
| `ci_failed` | `failed` | — | session.CIRetries >= MaxCIRetries | Set session.Error = "CI auto-fix exhausted"; emit `NotifyCIFailed`; write session.json |
| `working` | `changes_requested` | PR.ReviewStatus == `changes_requested` | — | Extract review comments; inject into agent context; write session.json |
| `changes_requested` | `ci_checking` | Agent force-pushes updated commits | PR.HeadSHA changed from last recorded | Re-request review; write session.json |
| `approved` | `mergeable` | PR.MergeableState == "mergeable" | — | Write session.json |
| `approved` | `ci_checking` | Additional CI runs triggered after approval | PR.CIStatus regresses to `running` | Write session.json |
| `mergeable` | `merged` | PR.State == "merged" (polling detects) | — | Write session.json; emit `NotifyMerged` |
| `merged` | `cleanup` | Immediate automatic transition | — | Begin worktree teardown; archive session files |
| `cleanup` | `done` | All worktrees removed, archives written | — | Write session.json; emit `NotifyKind: done` |

### 3.3 Lifecycle Manager Implementation

**File: `internal/lifecycle/lifecycle.go`**

```go
package lifecycle

import (
    "context"
    "fmt"
    "log/slog"
    "time"

    "github.com/altcode-ai/altcode/internal/workspace"
)

const (
    DefaultPollInterval = 10 * time.Second
    SpawnTimeout        = 30 * time.Second
    StuckThreshold      = 5 * time.Minute
    ActiveWindow        = 30 * time.Second
    ReadyThreshold      = 5 * time.Minute
    ActivityStaleness   = 5 * time.Minute
)

// Manager drives the workspace lifecycle state machine.
// It polls all active sessions on a fixed interval.
type Manager struct {
    store    *workspace.Store
    plugins  workspace.PluginSet
    log      *slog.Logger
    interval time.Duration
}

// NewManager creates a lifecycle manager with the given plugin set.
func NewManager(store *workspace.Store, plugins workspace.PluginSet, log *slog.Logger) *Manager {
    return &Manager{
        store:    store,
        plugins:  plugins,
        log:      log,
        interval: DefaultPollInterval,
    }
}

// Run starts the polling loop. Blocks until ctx is cancelled.
func (m *Manager) Run(ctx context.Context) error {
    ticker := time.NewTicker(m.interval)
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-ticker.C:
            m.pollAll(ctx)
        }
    }
}

// Advance drives one state machine step for a single session.
// Called by Run's poll loop and also by tests directly.
func (m *Manager) Advance(ctx context.Context, sess *workspace.WorkspaceSession) error {
    switch sess.Status {
    case workspace.WSSSpawning:
        return m.advanceSpawning(ctx, sess)
    case workspace.WSSWorking:
        return m.advanceWorking(ctx, sess)
    case workspace.WSSPROpen:
        return m.advancePROpen(ctx, sess)
    case workspace.WSSCIChecking:
        return m.advanceCIChecking(ctx, sess)
    case workspace.WSSCIFailed:
        return m.advanceCIFailed(ctx, sess)
    case workspace.WSSChangesRequested:
        return m.advanceChangesRequested(ctx, sess)
    case workspace.WSSApproved:
        return m.advanceApproved(ctx, sess)
    case workspace.WSSMergeable:
        return m.advanceMergeable(ctx, sess)
    case workspace.WSSMerged:
        return m.advanceMerged(ctx, sess)
    case workspace.WSSCleanup:
        return m.advanceCleanup(ctx, sess)
    }
    return nil
}
```

The `advanceWorking`, `advancePROpen`, etc. methods are each < 30 lines per the hard rule. They call helpers in `internal/lifecycle/reactions.go` (CI auto-fix construction), `internal/lifecycle/poll.go` (PR batch query), and `internal/lifecycle/activity.go` (activity detection cascade).

### 4.2 Branch Naming

Branches follow the pattern `altcode/{workspace-short-id}/{role}/{task-slug}`:

```
altcode/01hv/architect/add-auth-system
altcode/01hv/implementer/add-auth-system
altcode/01hv/reviewer/add-auth-system
```

Where `{workspace-short-id}` is the first 4 chars of the workspace ULID (for human readability). `{task-slug}` is the first 40 chars of the task, lowercased, spaces replaced with hyphens, non-alphanumeric stripped.

Collision handling: if the branch already exists (from a prior workspace), append `-{unix-timestamp}` to the branch name. This mirrors the pattern in `vendor/agent-orchestrator` (from `execenv/git.go:70-84`).

### 4.3 Worktree Setup

**File: `internal/workspace/worktree.go`**

```go
package workspace

import (
    "context"
    "fmt"
    "os"
    "os/exec"
    "path/filepath"
    "strings"
    "time"
)

// WorktreeWorkspace implements the Workspace interface using git worktrees.
type WorktreeWorkspace struct{}

func (w *WorktreeWorkspace) Name() string { return "worktree" }

func (w *WorktreeWorkspace) Setup(ctx context.Context, req WorkspaceSetupRequest) (*WorkspaceSetupResult, error) {
    branch := req.Branch
    err := runGitWorktreeAdd(ctx, req.GitRoot, req.WorktreePath, branch, req.BaseRef)
    if err != nil && isBranchExists(err) {
        branch = fmt.Sprintf("%s-%d", req.Branch, time.Now().Unix())
        err = runGitWorktreeAdd(ctx, req.GitRoot, req.WorktreePath, branch, req.BaseRef)
    }
    if err != nil {
        return nil, fmt.Errorf("worktree setup: %w", err)
    }
    baseCommit, _ := headCommit(req.WorktreePath)
    if err := symlinkDeps(req.WorktreePath, req.SymlinkDeps); err != nil {
        return nil, fmt.Errorf("symlink deps: %w", err)
    }
    return &WorkspaceSetupResult{
        Path:       req.WorktreePath,
        Branch:     branch,
        BaseCommit: baseCommit,
    }, nil
}

func (w *WorktreeWorkspace) Teardown(ctx context.Context, path string) error {
    gitRoot, err := findGitRoot(path)
    if err != nil {
        return os.RemoveAll(path) // fallback: just delete
    }
    cmd := exec.CommandContext(ctx, "git", "-C", gitRoot, "worktree", "remove", "--force", path)
    if err := cmd.Run(); err != nil {
        return os.RemoveAll(path)
    }
    return nil
}

func (w *WorktreeWorkspace) Checkpoint(ctx context.Context, path string, msg string) (string, error) {
    addCmd := exec.CommandContext(ctx, "git", "-C", path, "add", "-A")
    if err := addCmd.Run(); err != nil {
        return "", fmt.Errorf("git add: %w", err)
    }
    commitCmd := exec.CommandContext(ctx, "git", "-C", path, "commit", "--allow-empty", "-m", msg)
    if err := commitCmd.Run(); err != nil {
        if strings.Contains(err.Error(), "nothing to commit") {
            return headCommit(path) // return current HEAD, no new commit
        }
        return "", fmt.Errorf("git commit: %w", err)
    }
    return headCommit(path)
}
```

### 4.4 Turn Checkpoints

A turn checkpoint is a git commit created after every agent turn plus a JSON record appended to `.altcode/workspace/{id}/checkpoints/turn-{N:03d}.json`.

**Checkpoint JSON format:**

```json
{
  "turn": 7,
  "role": "implementer",
  "commit_hash": "abc123def456",
  "branch": "altcode/01hv/implementer/add-auth-system",
  "worktree": "/home/user/.altcode/worktrees/01hv.../implementer",
  "timestamp": "2026-04-07T14:22:11Z",

  "tokens_used": 4200,
  "cost_usd": 0.021

```

**Rollback procedure** (for `altcode rollback --turn 5 --role implementer`):

```bash

git reset --hard {checkpoint[5].commit_hash}
git push --force-with-lease origin {branch}
```

This gives users the "undo any agent action" feature described in the Cloud tier value proposition.

### 4.5 Symlinked Dependencies

Before spawning an agent, the workspace setup symlinks heavy dependency directories to avoid copying gigabytes of files:

```go
// defaultSymlinkDeps is the list of directories to symlink by default.
var defaultSymlinkDeps = []string{
    "node_modules",
    ".venv",
    ".tox",
    "vendor",       // Go vendor — but only if not using -mod=mod
    "__pycache__",
}

func symlinkDeps(worktreePath string, deps []string) error {
    // worktreePath/../../../{main-checkout}/node_modules → worktreePath/node_modules
    mainCheckout := findMainCheckout(worktreePath)
    for _, dep := range deps {
        src := filepath.Join(mainCheckout, dep)
        dst := filepath.Join(worktreePath, dep)
        if _, err := os.Stat(src); os.IsNotExist(err) {
            continue // src doesn't exist, skip
        }
        os.Remove(dst) // remove if already there
        os.Symlink(src, dst)
    }
    return nil
}
```

Note: Go's `-mod=mod` (set via GOFLAGS in this project's Makefile) does not use vendor/, so symlink is safe.

```go
// batchFlushLoop accumulates text events and flushes every 500ms.
// Tool calls flush immediately (structural events).
func batchFlushLoop(ctx context.Context, events <-chan agent.AgentEvent, out chan<- PhaseEvent, phase, role string) {
    var pending strings.Builder
    ticker := time.NewTicker(500 * time.Millisecond)
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            flushText(&pending, out, phase, role)
            return
        case ev, ok := <-events:
            if !ok {
                flushText(&pending, out, phase, role)
                return
            }
            if ev.Type == agent.EventText {
                pending.WriteString(ev.Content)
            } else {
                flushText(&pending, out, phase, role)
                trySendEvent(out, mapEvent(ev, phase, role))
            }
        case <-ticker.C:
            flushText(&pending, out, phase, role)
        }
    }
}
```

## 6. CI Auto-Fix Loop

### 6.1 Detection

The lifecycle manager polls PR CI status every `PollInterval` (10s) when in `ci_checking` state. The poll uses the SCM plugin's `CIStatus(ctx, headSHA)` method.

When CI transitions from `running` to `fail`, the lifecycle manager calls `advanceCIFailed`.

### 6.2 Auto-Fix Dispatch

**File: `internal/lifecycle/reactions.go`**

```go
package lifecycle

import (
    "context"
    "fmt"
    "strings"

    "github.com/altcode-ai/altcode/internal/workspace"
)

// DispatchCIFix routes CI failure output back to the primary agent,
// asking it to fix the failing checks and push a new commit.
func DispatchCIFix(ctx context.Context, sess *workspace.WorkspaceSession, ciLog string, store *workspace.Store) error {
    if sess.CIRetries >= sess.MaxCIRetries {
        return fmt.Errorf("ci fix: retry limit %d reached", sess.MaxCIRetries)
    }
    sess.CIRetries++

    primary := primaryAgent(sess)
    if primary == nil {
        return fmt.Errorf("ci fix: no primary agent in session")
    }

    // Truncate CI log to 8KB (from multica A11 pattern)
    log := ciLog
    if len(log) > 8192 {
        log = log[:8192] + "\n\n[log truncated]"
    }

    // Build fix prompt
    fixPrompt := buildCIFixPrompt(primary.Role, sess.Task, log, sess.CIRetries, sess.MaxCIRetries)

    // Update agent record with new task context
    primary.ActivityState = workspace.ActivitySpawning
    return store.SendMessage(ctx, sess.ID, primary.Role, fixPrompt)
}

func buildCIFixPrompt(role, task, ciLog string, attempt, max int) string {
    return fmt.Sprintf(`CI checks failed on your PR (attempt %d/%d).

Original task: %s

CI failure output:
%s

Please:
1. Identify the root cause of the failure.
2. Fix the failing checks.
3. Run the checks locally to verify (e.g. go build ./... && go vet ./... && go test ./...).
4. Commit the fix and push to your branch.

Do not create a new PR — push to the existing branch.`, attempt, max, task, ciLog)
}

func primaryAgent(sess *workspace.WorkspaceSession) *workspace.AgentRecord {
    // Primary agent is the implementer, or the first agent if no implementer
    for _, rec := range sess.Agents {
        if rec.Role == "implementer" {
            return rec
        }
    }
    for _, rec := range sess.Agents {
        return rec
    }
    return nil
}
```

## 9. Shared Context Model

### 9.1 The `.altcode/workspace/{id}/context.md` File

This is the shared notepad for all agents in a workspace. It is:
- Readable by all agents (injected into CLAUDE.md / AGENTS.md at spawn time)
- Writable by the orchestrator (lifecycle manager appends decisions/transitions)
- Human-editable (operator can add context during a running workspace)

**Format:**

```markdown
# Workspace Context: add-auth-system

**Task:** Add JWT authentication with refresh tokens to the API

**Created:** 2026-04-07T14:00:00Z
**Status:** working

## Agent Assignments

- **architect** (claude): Design the auth system. Output a concrete plan to context.md.
- **implementer** (codex): Implement the design from the architect's plan.
- **reviewer** (claude): Review the implementer's PR for correctness and security.

## Architect's Design (Phase: design — COMPLETED)

[Contents appended by architect agent after completing design phase]
JWT flow: ...
Refresh token strategy: ...
Database schema: ...

## CI Fix Attempt 1

CI failed on PR#47 at 14:22:11Z. Error:
  FAIL internal/auth [build failed]
  auth_test.go:45: undefined: TokenClaims

Dispatched fix to implementer at 14:22:15Z.
```

### 9.2 How Agents Access Shared Context

At spawn time, `InjectContext` (upgraded from `internal/orchestra/context.go`) reads `context.md` and appends it to the agent's native context file:

- `claude` backend: appended to `{worktree}/CLAUDE.md`
- `codex` / `opencode` backend: appended to `{worktree}/AGENTS.md`

The injection happens:
1. At initial agent spawn
2. When the agent is resumed after CI fix or review changes (fresh injection with current context.md)
3. When the operator injects context via `Ctrl+S` / `/send`

Prior phase outputs (from `orchestra.PhaseResult.Outputs`) are written to context.md by the lifecycle manager after each phase completes, making them available to downstream agents.

### 9.3 Context Overflow Prevention

Total injected context is capped:
- `context.md` content injected: max 32KB (truncated with `[truncated]` marker)
- Prior phase outputs per phase: max 32KB (existing behavior in `orchestra/context.go`)
- CI failure log: max 8KB (multica A11)
- Review comments: max 16KB

When a context.md grows beyond 64KB, the lifecycle manager runs a compaction: it keeps the last 5 CI fix attempts, the last 3 review cycles, and the full design outputs. Older content is archived to `.altcode/workspace/{id}/context-archive.md`.

### 9.4 Agent Visibility Into Each Other's Progress

Each agent can see:
1. `context.md` (shared notepad) — updated by orchestrator
2. `agents/{role}.json` — other agents' branch names, PR URLs, CI status

This is intentionally read-only for agents. Agents communicate through git artifacts (branches, PRs, commits) not direct messaging. This is the "git as coordination medium" design principle.

The `.altcode/workspace/{id}/agents/` directory is injected as a structured block into context.md at spawn time:

```markdown
## Workspace Agents Status

| Role | Branch | PR | CI | Activity |
|------|--------|----|----|----------|
| architect | altcode/01hv/architect/... | PR#46 | pass | exited(0) |
| implementer | altcode/01hv/implementer/... | PR#47 | running | active |
| reviewer | altcode/01hv/reviewer/... | — | — | ready |
```

### 10.3 Config Loading

**File: `internal/workspace/config.go`**

```go
package workspace

import (
    "fmt"
    "os"
    "path/filepath"

    "gopkg.in/yaml.v3"
)

// Config holds the parsed .altcode/config.yaml.
type Config struct {
    Workspace WorkspaceConfig `yaml:"workspace"`
    SCM       SCMConfig       `yaml:"scm"`
    Notifier  NotifierConfig  `yaml:"notifier"`
    Agents    AgentsConfig    `yaml:"agents"`
    Workflows WorkflowsConfig `yaml:"workflows"`
    Plugins   PluginsConfig   `yaml:"plugins"`
}

// LoadConfig reads .altcode/config.yaml from projectRoot.
// Returns a Config with all defaults applied if the file doesn't exist.
func LoadConfig(projectRoot string) (*Config, error) {
    path := filepath.Join(projectRoot, ".altcode", "config.yaml")
    data, err := os.ReadFile(path)
    if os.IsNotExist(err) {
        return DefaultConfig(), nil
    }
    if err != nil {
        return nil, fmt.Errorf("workspace config: %w", err)
    }
    var cfg Config
    if err := yaml.Unmarshal(data, &cfg); err != nil {
        return nil, fmt.Errorf("workspace config parse: %w", err)
    }
    applyDefaults(&cfg)
    if err := validateConfig(&cfg); err != nil {
        return nil, fmt.Errorf("workspace config invalid: %w", err)
    }
    return &cfg, nil
}
```

The `WorkspaceConfig`, `SCMConfig`, `NotifierConfig`, etc. structs mirror the YAML above, with explicit `yaml` tags and `time.Duration` fields for interval/timeout values (using `gopkg.in/yaml.v3`'s duration parsing).

Env var expansion happens at load time for `token` fields: any value starting with `$` is resolved via `os.Getenv`.

## 12. Data Storage

### 12.1 Design Principles

No database. Flat files only. This matches `vendor/agent-orchestrator/CLAUDE.md`'s storage design ("No database. Flat files + memory") and serves two goals:

1. **Debuggability:** Every piece of state is a readable file. `cat session.json | jq .status` gives the lifecycle state. No need for a DB CLI.
2. **Portability:** The workspace directory can be copied to another machine and resumed there (for future Cloud tier sync).

### 12.2 Directory Layout (Complete)

```
{project_root}/
└── .altcode/
    ├── config.yaml                          # workspace config (YAML)
    ├── bin/                                 # PATH wrapper binaries (executable)
    │   ├── gh                              # intercepts gh pr create, captures PR#
    │   └── git                             # intercepts git commit, captures SHA
    └── workspace/
        └── {workspace-id}/                  # one directory per workspace
            ├── session.json                 # WorkspaceSession (all fields)
            ├── context.md                   # shared notepad (markdown)
            ├── context-archive.md           # compacted old context (optional)
            ├── activity.jsonl               # append-only activity log
            ├── agents/
            │   ├── {role}.json             # AgentRecord for each role (live)
            │   └── ...
            └── checkpoints/
                ├── turn-001.json            # TurnCheckpoint
                ├── turn-002.json
                └── ...

{HOME}/.altcode/
├── worktrees/
│   └── {workspace-id}/
│       ├── architect/                       # git worktree root
│       ├── implementer/
│       └── reviewer/
└── bin/                                     # global PATH wrappers (alternative location)
    ├── gh
    └── git
```

The per-workspace worktrees are stored in `~/.altcode/worktrees/` (not inside the project) to prevent:
- Git detecting nested worktrees in the project directory
- Editors (VS Code, etc.) scanning worktree files as part of the project
- Accidental `git add` of worktree files from the main checkout

### 12.3 session.json Schema

The `WorkspaceSession` struct (Section 2.3) serializes to JSON using `encoding/json`. All time.Time fields serialize as RFC3339. Duration fields (e.g. `poll_interval`) are stored as strings ("10s").

The file is written atomically: write to `session.json.tmp`, then `os.Rename` to `session.json`. This prevents corrupt reads if the process is killed mid-write.

```go
// SaveSession writes sess to .altcode/workspace/{id}/session.json atomically.
func (s *Store) SaveSession(sess *WorkspaceSession) error {
    data, err := json.MarshalIndent(sess, "", "  ")
    if err != nil {
        return err
    }
    path := s.sessionPath(sess.ID)
    tmp := path + ".tmp"
    if err := os.WriteFile(tmp, data, 0o644); err != nil {
        return err
    }
    return os.Rename(tmp, path)
}
```

## 13. Error Handling and Recovery

### 13.1 Agent Process Crash

**Detection:** `Agent.IsProcessRunning()` returns false during the poll cycle.

**Response:**
1. Set `AgentRecord.ActivityState = ActivityExited`, `AgentRecord.ExitCode = N`
2. Read the last turn checkpoint to determine how far the agent got
3. Classify the crash:
   - `ExitCode == 0`: Normal exit. If PR exists, continue lifecycle normally. If no PR, mark as `blocked` and notify (orange).
   - `ExitCode != 0`: Abnormal exit. Attempt restart up to 2 times with `--resume` if session ID is known.
   - Context overflow (detected via exit code + stderr containing "context length"): Do not restart. Route to compaction flow — truncate oldest messages and restart.
4. After 2 restart attempts: set `WorkspaceStatus = WSSFailed`, write `session.Error`, emit `NotifyError`.

**Restart logic** is in `internal/lifecycle/reactions.go:RestartAgent()`:

```go
func RestartAgent(ctx context.Context, rec *workspace.AgentRecord, sess *workspace.WorkspaceSession, plugins workspace.PluginSet) error {
    if rec.RestartCount >= 2 {
        return fmt.Errorf("agent %s: restart limit reached", rec.Role)
    }
    rec.RestartCount++
    agentPlugin := plugins.Agents[rec.Backend]
    agentSess := buildAgentSession(rec, sess)
    cmd, err := agentPlugin.RestoreCommand(agentSess)
    if cmd == nil || err != nil {
        cmd, err = agentPlugin.LaunchCommand(agentSess)
    }
    if err != nil {
        return err
    }
    handle, err := plugins.Runtime.Spawn(ctx, cmd, agentSess.Env, rec.WorktreePath)
    if err != nil {
        return err
    }
    rec.RuntimeHandleID = handle.ID
    rec.ActivityState = workspace.ActivitySpawning
    return nil
}
```

### 13.2 Timeout

Per-agent timeout is configured via `agents.roles.{role}.timeout` (default: 30m). Enforced by the lifecycle manager:

```go
// In advanceWorking:
if time.Since(rec.SpawnedAt) > agentTimeout && rec.ActivityState == ActivityIdle {
    // Agent has been idle past timeout: treat as graceful exit
    plugins.Runtime.Kill(RuntimeHandle{ID: rec.RuntimeHandleID})
    rec.ActivityState = ActivityExited
    rec.ExitCode = -1 // timeout
}
```

### 13.3 Stuck Detection

An agent is stuck when `ActivityState == ActivityWaitInput` or `ActivityState == ActivityBlocked` for more than `ActivityStaleness` (5 minutes).

Detection is in the activity cascade (`internal/activity/activity.go`):

```go
// CheckStuck returns true if the agent has been in waiting_input or blocked
// for longer than ActivityStaleness.
func CheckStuck(rec *workspace.AgentRecord) bool {
    if rec.ActivityState != ActivityWaitInput && rec.ActivityState != ActivityBlocked {
        return false
    }
    return time.Since(rec.ActivityUpdatedAt) > ActivityStaleness
}
```

When stuck is detected:
1. Set attention priority to `AttentionRed`
2. Fire terminal bell (if `workspace.notify_bell == true`)
3. Emit `NotifyNeedsAttention`
4. Write activity.jsonl entry with `"type":"agent_stuck"`

The operator is expected to either:
- `/send {role} <message>` to unblock the agent
- `altcode rollback` to a prior turn and retry
- Abort the workspace

### 13.4 Context Overflow

Detected when an agent process exits with a non-zero code and stderr contains any of:
- "context length" / "context window" / "max_tokens" / "too many tokens"

Response:
1. Calculate current context size from turn checkpoint token counts
2. If `AgentRecord.TurnCount > 5`: truncate the oldest 50% of turns by rolling back to `turn-{TurnCount/2:03d}.json` checkpoint
3. Restart agent with `--resume` (the session state carries the truncated history)
4. Write activity.jsonl entry `{"type":"context_overflow","tokens":N,"strategy":"rollback_truncate"}`

If context overflow persists after truncation, the workspace transitions to `WSSFailed`.

### 13.5 Merge Conflicts

Detected when `PR.MergeableState == "conflicting"` during the `approved` or `mergeable` state.

Response:
1. Stay in `approved` state (do not transition to `mergeable`)
2. Build a conflict resolution prompt:

```
Your PR has merge conflicts with the base branch ({base}).

Please:
1. git fetch origin
2. git rebase origin/{base}
3. Resolve all conflicts (look for <<<<<<, =======, >>>>>>>)
4. git push --force-with-lease origin {branch}

The conflicts are in the following files:
{list from GitHub API}
```

3. Dispatch to the agent via `SendMessage`
4. Agent resolves conflicts, force-pushes, PR becomes mergeable

### 13.6 GitHub API Rate Limiting

The SCM plugin implements exponential backoff on 429 responses:

```go
func (g *GitHubSCM) withRetry(ctx context.Context, fn func() error) error {
    backoff := 1 * time.Second
    for attempt := 0; attempt < 5; attempt++ {
        err := fn()
        if err == nil {
            return nil
        }
        if !isRateLimitError(err) {
            return err
        }
        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-time.After(backoff):
            backoff *= 2
        }
    }
    return fmt.Errorf("github: rate limit retry exhausted")
}
```

The batch GraphQL PR query (Section 6.4) is the primary tool for avoiding rate limit issues — one query for all PRs instead of N queries.

## 14. Security

### 14.1 API Key Isolation

API keys (ANTHROPIC_API_KEY, OPENAI_API_KEY, GITHUB_TOKEN, etc.) are inherited from the parent process environment. They are never:
- Written to any file under `.altcode/` (including session.json, context.md, activity.jsonl)
- Injected into agent context files (CLAUDE.md, AGENTS.md)
- Logged to activity.jsonl
- Included in checkpoint JSON files
- Transmitted via the PATH wrappers (`~/.altcode/bin/gh`, `~/.altcode/bin/git`)

The `AgentSession.Env` field is built by taking `os.Environ()` and merging in the `Agent.Environment()` additions. It is never serialized to disk.

### 14.2 Worktree Sandboxing

Each agent operates in an isolated git worktree. The isolation is:
- **File system:** The agent can only write within its worktree path (enforced by setting `cmd.Dir = rec.WorktreePath`)
- **Git:** The agent commits to its own branch; it cannot directly modify the base branch
- **Process:** Each agent runs as a subprocess of the altcode process, inheriting the user's UID/GID. No additional privilege escalation.

The permission evaluator in `internal/permission/` is the additional guard for agents using the internal engine. For external CLI agents (claude/codex/etc.), permission control is delegated to the agent's own permission mode (`bypassPermissions` for automated workflows, which is equivalent to the operator giving blanket approval).

**Note:** `bypassPermissions` means the agent can execute arbitrary shell commands within its worktree. This is intentional — automated workflows require this. The worktree boundary is the safety boundary, not individual tool permissions.

### 14.3 PATH Wrapper Safety

The `~/.altcode/bin/gh` and `~/.altcode/bin/git` wrappers only intercept specific subcommands:
- `gh pr create` — captures `--html-url` from output, writes to `agents/{role}.json`
- `git commit` — captures the new commit hash, writes a turn checkpoint
- All other invocations are passed through unchanged

The wrappers are implemented as shell scripts or Go binaries that exec the real `gh`/`git` binaries after capturing their output. They do not modify the commands or inject arguments.

### 14.4 No Secret Injection into Context

The `buildContextContent` function (`internal/orchestra/context.go`) and the upgraded `InjectContext` (`internal/workspace/wsctl/inject.go`) must never include:
- Any string that matches the patterns in the CLAUDE.md secret checklist (`sk-`, `ghp_`, `AKIA`, etc.)
- Contents of `.env` files
- Contents of `~/.claude/.credentials.json` or `~/.codex/auth.json`

A static check in the context injection path validates that injected content does not contain known secret patterns before writing.

### 14.5 `.gitignore` Requirements

The following paths must be in the project's `.gitignore` (or altcode adds them automatically during `workspace init`):

```gitignore
# altcode workspace state
.altcode/workspace/
.altcode/bin/

# altcode worktrees are in ~/.altcode/worktrees, not here
# But if a user accidentally runs workspace init in a symlinked location:
.ao/
```

## 18. Critical Implementation Notes

### 18.1 Function Length Discipline

Every function in the new packages must be <= 30 lines. The lifecycle transitions are the biggest risk area: `advanceWorking` has many conditions. Split into:
- `detectPRCreation(ctx, sess) (int, error)` — returns PR number or 0
- `detectCITransition(ctx, rec) CICheckStatus` — returns new CI status
- `detectReviewTransition(ctx, rec) ReviewStatus` — returns new review status

Each of these is < 15 lines. `advanceWorking` calls them and acts on results.

### 18.2 No Circular Imports

Import hierarchy (strict one-direction flow):

```
cmd/altcode → internal/tui, internal/lifecycle, internal/workspace, internal/scm
internal/tui → internal/workspace, internal/orchestra, internal/event
internal/lifecycle → internal/workspace, internal/scm, internal/activity, internal/checkpoint
internal/workspace/backends → internal/workspace, internal/activity
internal/workspace → (no internal/... imports — only stdlib + external deps)
internal/scm → (no internal/... imports)
internal/activity → (no internal/... imports)
internal/orchestra → internal/wfdef, internal/agent, internal/wsctl
internal/wsctl → internal/workspace (for config only)
```

The `internal/workspace` package must NOT import `internal/engine`, `internal/tui`, or `internal/lifecycle`. It is the leaf package that everything else imports.

### 18.3 The Activity Detection Cascade

Every agent backend's `ActivityState()` method must implement the full cascade from `vendor/agent-orchestrator/CLAUDE.md`:

```
1. Process check (isProcessRunning) → exited
2. Actionable states (waiting_input/blocked) from JSONL → return immediately
3. Native signal (agent API / commit timestamps) → active/ready/idle
4. JSONL entry fallback (age-based decay) → active/ready/idle
5. Return nil only if genuinely no data
```

Step 4 is mandatory. Skipping it causes stuck detection to fail. This was a documented production bug in the reference implementation.

### 18.4 Tool Result Truncation

All tool results from agents must be truncated at 8KB before writing to activity.jsonl or injecting into context. This is the multica A11 pattern applied consistently.

### 18.5 Atomic File Writes

All JSON file writes (session.json, agents/{role}.json, checkpoints/turn-N.json) use the atomic write pattern:
1. `os.WriteFile(path+".tmp", data, 0o644)`
2. `os.Rename(path+".tmp", path)`

This prevents corruption when the process is killed mid-write. JSONL files use append (`O_APPEND|O_CREATE|O_WRONLY`) which is safe because each line is an atomic write at the OS level for short lines (< 4KB).

### 18.6 Non-Blocking Channel Operations

All channel sends in the new packages use the `trySend` pattern:

```go
func trySend[T any](ch chan<- T, v T) {
    select {
    case ch <- v:
    default:
    }
}
```

Never block on a channel send in a goroutine that is also reading from another channel. Deadlock is the most common failure mode in orchestration systems.

### 18.7 Context Propagation

All I/O operations accept `context.Context` as the first parameter. All goroutines started by the lifecycle manager must respect `ctx.Done()`. The lifecycle manager's `Run(ctx)` is the root context holder; all child contexts are derived via `context.WithTimeout` or `context.WithCancel`. No goroutine should outlive the context.

### 18.8 SHA-based Workspace Hash

Following the agent-orchestrator pattern, the workspace storage root uses a hash prefix to prevent collisions across multiple checkouts of the same repo:

```go
// WorkspaceRoot returns the per-project workspace root directory.
// Hash = first 12 chars of SHA-256 of the project's git remote URL.
// This prevents collision when the same repo is checked out multiple times.
func WorkspaceRoot(gitRemoteURL string) string {
    h := sha256.Sum256([]byte(gitRemoteURL))
    prefix := fmt.Sprintf("%x", h[:6])
    home, _ := os.UserHomeDir()
    return filepath.Join(home, ".altcode", "worktrees", prefix)
}
```

The `.altcode/workspace/` directory (in the project root) uses the ULID directly, without a hash, since it's already per-project.

## Appendix C: Design Decisions and Trade-offs

**Decision: Flat files, no DB for workspace state.**
Trade-off: No atomic multi-record transactions (e.g., updating session.json + activity.jsonl atomically). Mitigation: The session.json is the authoritative record; activity.jsonl is append-only and can be replayed. In practice, the lifecycle manager holds state in memory and writes to disk; a crash loses at most one poll cycle (10s) of state.

**Decision: Worktrees in `~/.altcode/worktrees/`, not in the project.**
Trade-off: More complex path management. Requires computing `WorkspaceRoot` from git remote URL. Benefit: No nested `.git` issues, no editor interference, cleaner project directory.

**Decision: `bypassPermissions` for all automated workspace agents.**
Trade-off: Agents have full shell access within their worktree. This is intentional — automated workflows cannot function with permission prompts. The worktree boundary is the safety boundary. Users who want stricter control can set `permission_mode: default` in `agents.roles.{role}` config, but this will cause agents to hang on prompts in automated workflows.

**Decision: 10s poll interval for CI/review status.**
Trade-off: Up to 10s delay between CI status change and altcode response. Alternative: GitHub webhooks (real-time). Webhooks require a public URL and server infrastructure, which contradicts the local-first design. For v0.8, polling is the right choice. Webhooks are a Cloud tier feature.

**Decision: Single shared `context.md` (not per-agent).**
Trade-off: All agents see all prior outputs, including outputs not directly relevant to their role. Benefit: Agents can make informed decisions based on the full workspace picture. The 32KB injection cap prevents context overflow from a bloated context.md.

**Decision: Borrow `internal/orchestra/` for workflow execution, not replace it.**
The existing orchestra phase engine is solid. The v0.8 workspace engine uses it as a sub-component (for workflow-driven workspaces) rather than replacing it. The `PrePhaseHook`/`PostPhaseHook` extension points allow workspace-aware behavior without modifying the core phase logic.

### E5. Turn Checkpoint Trigger (CRITICAL)

Checkpoints triggered by lifecycle manager poll loop detecting `active → ready/idle` transition — NOT by git PATH wrapper. The PATH wrapper is ONLY for metadata capture (commit hashes, PR URLs).

```go
func (m *Manager) checkpointOnTurnEnd(ctx context.Context, sess *WorkspaceSession, rec *AgentRecord) (bool, error) {
    prev := rec.ActivityState
    det, _ := m.plugins.Agents[rec.Backend].ActivityState(ctx, buildAgentSession(rec, sess))
    if det == nil { return false, nil }
    rec.ActivityState = det.State
    wasActive := prev == ActivityActive
    nowResting := det.State == ActivityReady || det.State == ActivityIdle
    if !wasActive || !nowResting { return false, nil }
    rec.TurnCount++
    hash, err := m.plugins.Workspace.Checkpoint(ctx, rec.WorktreePath,
        fmt.Sprintf("altcode: checkpoint turn-%03d [%s]", rec.TurnCount, rec.Role))
    if err != nil { return false, err }
    rec.HeadSHA = hash
    return true, nil
}
```

### R3-3. LastCheckedSHA Assignment (NEW-3)

`LastCheckedSHA` is assigned in TWO places:

1. **When entering `ci_checking` state** — in `advanceWorking`:
```go
// detectSHAChange checks if agent pushed new commits to an existing PR.
func detectSHAChange(rec *AgentRecord) bool {
    if rec.PRID > 0 && rec.HeadSHA != rec.LastCheckedSHA {
        rec.LastCheckedSHA = rec.HeadSHA  // <-- ASSIGNMENT HERE
        return true // transition to ci_checking
    }
    return false
}
```

2. **When CI completes (pass or fail)** — in `advanceCIChecking`:
```go
func (m *Manager) advanceCIChecking(ctx context.Context, sess *WorkspaceSession, rec *AgentRecord) {
    status := m.pollCI(ctx, rec)
    rec.CIStatus = status
    rec.LastCheckedSHA = rec.HeadSHA  // <-- ASSIGNMENT HERE (prevents re-check of same SHA)
    if status == CIPass {
        // transition to approved/mergeable check
```

This ensures the guard `HeadSHA != LastCheckedSHA` is false after CI has been checked for a given SHA, preventing infinite re-entry.
