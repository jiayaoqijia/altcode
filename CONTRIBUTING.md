## How to Contribute

### Bug Reports and Small Fixes

1. Check [existing issues](https://github.com/YOUR_ORG/YOUR_REPO/issues) first.
2. Open a new issue with reproduction steps.
3. Small fixes (typos, docs, one-line bugs) can go straight to a PR.

### New Features

1. Open a [Discussion](https://github.com/YOUR_ORG/YOUR_REPO/discussions) first.
2. Describe the problem, your proposed solution, and any alternatives.
3. Wait for maintainer feedback before starting work.
4. Once approved, open a PR referencing the discussion.

### Questions

- Use [Discussions](https://github.com/YOUR_ORG/YOUR_REPO/discussions) or [Discord](https://discord.gg/YOUR_INVITE).
- Issues are for bugs and feature requests, not general questions.

## Development Setup

### Prerequisites

- Node.js v22+
- Git

### Getting Started

```bash
git clone https://github.com/YOUR_ORG/YOUR_REPO.git
cd YOUR_REPO
npm install
```

### Running Tests

```bash
# Run full test suite
npm test

# Run with coverage
npm run test:coverage

# Run a specific test file
npm test -- path/to/test.ts
```

### Building

```bash
npm run build
```

### Linting

```bash
npm run lint
```

## Pull Request Process

1. Fork the repo and create a feature branch from `main`.
2. Make your changes with clear, focused commits.
3. Add or update tests for your changes.
4. Ensure all checks pass: `npm run build && npm run lint && npm test`
5. Open a PR with a clear description of what and why.
6. Link any related issues.

### PR Guidelines

- Keep PRs focused. One feature or fix per PR.
- Write descriptive commit messages.
- Update documentation if your change affects public APIs or behavior.
- Add a CHANGELOG entry for user-facing changes.

### AI-Generated Code

AI-assisted contributions are welcome. If your PR was substantially generated by an AI coding tool, please note that in the PR description for transparency. The same quality standards apply to all contributions regardless of how they were written.

## Code Style

- Follow the existing code patterns in the repository.
- Use TypeScript for type safety where applicable.
- Write self-documenting code; add comments only for non-obvious logic.
- Keep functions focused and small.

## Commit Messages

Use clear, descriptive commit messages:

```
feat: add user authentication endpoint
fix: resolve race condition in connection pool
docs: update API reference for v2 endpoints
test: add integration tests for payment flow
chore: update dependencies
```
